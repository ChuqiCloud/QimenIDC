# 1.3.5_7：运行中虚拟机改配事务修复

## 问题与接口

1.3.5_5、1.3.5_6 的 `updateVm` 在持有 `vmhost` 行锁的事务内创建关机任务并同步等待关机。任务未提交，定时执行器无法读取，最终导致改配超时、并发请求锁等待。

以下接口共同使用修复后的服务，参数和同步返回方式保持兼容：

- `PUT /{adminPath}/updateVm`（也支持 POST）
- `POST /api/v1/pve/updateVm`（也支持 PUT）

## 修复行为

- 接口挂起调用方事务，在短事务内检查迁移占用、校验流量参数和系统盘缩容请求，并登记“修改虚拟机”任务（现有任务类型 2）。
- 同一实例有未完成改配时，重复请求直接返回“该虚拟机正在修改配置，请等待当前改配完成后再试”。迁移、删除、重装、电源及其他已有受保护的变更入口，也会识别正在执行的改配任务并拒绝并发操作。
- 关机任务单独提交后，再在事务外查询 PVE、等待关机和执行改配。数据库设置、硬件字段与后续开机任务在短事务内保存。
- 改配任务记录完成或失败结果。运行异常进入审计日志 `exception`，保留底层锁等待、超时等原因并脱敏；管理端保留业务错误详情。
- 创建关机任务失败时回滚其短事务，避免遗留“强制关机中”状态。改配失败时取消仍排队的本次关机子任务；调度器通过条件更新认领任务，并检查改配父任务，避免执行已取消的旧任务。已开始执行的关机请求无法撤回，仍在关机中的实例会拒绝新的硬件改配。
- 强制关机定时任务只写回电源状态，避免旧实例快照覆盖刚提交的流量配额、用量和硬件配置。
- 沿用现有硬件改配后的延迟开机行为。流量参数单独修改不触发关机，也不会回写并覆盖并发更新的流量用量快照。

本次复用现有 `task` 表，无数据库结构变更，无需额外 SQL。

## 同类方法审计

`power`、`resetVmOs`、`deleteVm`、`deleteVmToRecycle`、`unDeleteVm`、`resetVmPassword` 和 IP 变更后的重启流程，均在创建异步任务后返回，没有发现本次“等待未提交任务”的自锁。

数据盘、快照和备份的部分方法仍在事务内调用 PVE。`rollbackVmBackup` 还会直接强制关机并轮询，最长约 5 分钟；它不依赖未提交的关机任务，但仍有长时间占用行锁的风险。本次未改动备份还原流程，其异步 PVE 还原任务需要单独设计完整的占用与结束状态管理。

## 验证范围

回归测试使用真实 Spring 事务代理、H2 数据库和独立数据库连接，配合模拟 PVE 验证任务在等待前已提交、等待时无数据库事务、并发改配和迁移被拒绝，以及失败任务状态与审计日志。生产 MariaDB 和真实 PVE 的端到端验证仍需部署后进行。

已通过 `gradlew clean test bootJar --offline --no-daemon`，全量 349 个测试通过，无失败或跳过。生成 `build/libs/QimenIDC-Server.jar`，包内版本为 `1.3.5_7`，业务类保持 Java 17 字节码。
