# 数据库凭据加密

从 `1.3.4_3` 起，`master.password/csrf_token/ticket`、`vmhost.password`、
`vncinfo.password` 通过 MyBatis 字段处理器写入 AES-256-GCM 密文。每次写入生成随机
nonce，密文带 `QIDENC:1:` 版本标记和认证标签。密码只在服务内部读取时解密，配置文件没有加密密钥。

密钥按项目要求固化在 `security/StoredPasswordCipher.java`。必须保留该密钥才能读取已存数据；
不能直接更换常量后上线，否则旧密文无法解密。代码仓库及 JAR 需要受控，因为取得代码或反编译产物的人员也能取得密钥。

数据库结构升级会扩展密码列，避免密文超过原有 `varchar(255)`。应用启动时在节点预热和任务执行前，
通过事务迁移历史主表密码、VNC 副本以及所有类型 `task.params` 中的密码字段；任务参数仍是合法 JSON。
已加密值会校验后保留，重启不会重复加密。任一密文损坏或参数格式错误会回滚本次数据迁移并中止启动，
错误消息不带原始凭据。上线前应备份数据库；备份中已有的明文不会因主库迁移而改变。

节点密码和认证票据禁止 Jackson、Fastjson 以及实体 `toString()` 输出；接口仍可提交新密码。
局部编辑节点时省略密码字段会保留原值。当前版本已删除 SSH 专用字段和相关调用，不再恢复 SSH 密码接口。
任务接口保留进度等普通参数，递归移除密码、票据、token 等敏感字段。虚拟机用户密码的现有授权查询保持兼容魔方插件。

API 审计日志使用同一套敏感字段规则。启动迁移会脱敏历史请求体、响应体、查询参数和错误消息中的密码字段；
日志保存及接口读取时也会脱敏。损坏或截断的 JSON、无法解析的查询参数用固定占位替换，
对外通用异常响应使用固定提示。此操作不改变日志时间、操作人、URI 等审计元数据，
也不处理已经导出到磁盘或备份中的历史日志。
